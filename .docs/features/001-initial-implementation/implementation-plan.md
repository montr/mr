## 2. Current implementation and affected components

1. `MonoReport/Services/CachedResultWriter.cs` currently distributes text by UTF-16 length. Its replacement loop can divide a surrogate pair between XML text elements. Preserve its existing run distribution and control-character conversion rather than introducing a new renderer.
2. `MonoReport/Services/OoxmlFieldParser.cs` tracks complex frames but returns only MERGEFIELD references. Its structural inspection must retain enough information about all Word field kinds to identify nested cached-result fields. `FieldCodeParser` must retain its existing evaluation scope; PAGE/IF detection does not introduce evaluation.
3. `MonoReport/Services/RegionParser.cs` currently returns only outer regions. Validation needs matched intervals at every logical depth, sibling relationships, and physical footprints based on its existing `GetBlocks` selection. Rendering can retain its existing outer-region projection. Small private/local metadata or focused model changes to `FieldFrame`/`Region` are permissible only if needed for these validations.
4. `MonoReport/Services/DocumentRenderer.cs` will expose focused nonmutating preflight collaboration with the existing field and region parsers. It must not resolve JSON values, format data, write cached results, remove markers, or clone/remove blocks during preflight.
5. `MonoReport/Services/MergeEngine.cs` will load all currently rendered story XML trees into per-operation storage, preflight every tree, then render/save them. Preserve package enumeration, public API, caller-owned streams, and existing `MergeContext` isolation.
6. Tests will be added to `FieldTests.cs`, `RegionTests.cs`, `OoxmlEdgeTests.cs`, `MergeEngineTests.cs`, and `CliTests.cs` as appropriate. Extend `Docx.cs` only for focused valid fixtures, story reads, and shared assertions. No production CLI change is expected: `CliApplication.Run` already writes output only after `Merge` returns and catches `TemplateException`.
7. All service dependencies remain externally injected class instances; any new collaborator requires consumer/test composition changes rather than default dependency construction. Template trees, metadata, and counters belong to the merge operation, not reusable service fields. Prefer primary constructors and preserve null validation. No unrelated refactoring or sample changes are planned.

## 4. F1 — Unicode-safe cached-result distribution

1. Correction: in `CachedResultWriter.Write`, calculate the existing nominal segment length; if its interior end lies between a high surrogate and its following low surrogate, advance that end by one UTF-16 code unit. Derive the next offset from the adjusted segment length. Keep the final segment remainder, existing empty runs, original field instructions/markers, and complete run properties. Do not introduce grapheme-cluster or malformed-Unicode policies.
2. F1-R1 Red reproducer: valid complex MERGEFIELD with two one-character cached text runs and distinct formatting; replacement is U+1F600. The expected merge must serialize and yield exact text. Current serialization fails with a split surrogate. Compare every original run property subtree and field-code/marker sequence after success; do not rely only on concatenated text.
3. F1-R2 parameterized boundary regressions: simple and complex outer fields; three or more text nodes; unequal lengths including zero-length nodes; several surrogate pairs at successive nominal boundaries; mixed BMP/non-BMP text; shorter replacement exhausting later runs and longer replacement using the final remainder. Assert no text node contains an unpaired surrogate, exact aggregate text, retained run count/order and full properties, and valid output package.
4. F1-R3 repeated scalar merge: merge non-BMP text, then re-merge the generated output with a different mixed value including additional non-BMP text. Validate each output, exact values, instruction/marker preservation, run properties, and template immutability. Include a BMP second value to verify no stale character content remains.
5. F1-P1 positive controls retain existing no-cached-result separator insertion, fragmented complex instructions, simple fields, hyperlink result containers, BMP text, whitespace/XML characters, tabs and line breaks, standard/custom formatting, and MERGEFORMAT behavior. Assert their existing structural behavior rather than adding a stronger cross-run CRLF contract.

## 5. F2 — reject nested Word fields in cached results

1. Correction: add read-only field-structure validation within `OoxmlFieldParser` responsibility. Identify simple field descendants and matching complex begin/separator/end intervals for every Word field type. For each ordinary or technical-marker MERGEFIELD, reject a nested simple field or complex begin in its cached-result boundary. A simple outer field owns descendant result content; a complex outer owns only content after its own separator and before its matching end. A complex outer without a separator has no cached-result interval. Instruction nesting is not covered by this restriction.
2. F2-R1 Red reproducer: valid complex outer MERGEFIELD Name with a nested complex PAGE cached field. Expect `TemplateException`; the existing engine succeeds and loses PAGE codes. F2-R2 Red reproducer: nested complex MERGEFIELD Inner in the same location; expect contextual `TemplateException`, while current rendering produces detached-node `InvalidOperationException`. Validate original fixtures before invoking the engine to exclude malformed-input artifacts.
3. F2-R3 matrix: simple/complex outer versus simple/complex nested fields; PAGE, MERGEFIELD, and another non-merge kind such as IF; deeper nesting; nested complex field without its own separator; nested simple field with no cached text. Include simple and complex TableStart/TableEnd markers, including an empty collection, to prove marker removal does not bypass rejection.
4. F2-P1 positive controls: independent simple/complex sibling MERGEFIELDs and sibling PAGE/IF fields, ordinary non-merge fields, no cached result, and existing fragmented/cross-paragraph complex fields. Compare exact non-merge instructions/markers/content and retained merge codes. A structurally valid nested field in an instruction, outside any MERGEFIELD cached interval, must not acquire this new rejection; preserve existing behavior without promising new evaluation semantics.
5. F2-D1 assertions: exact exception type `TemplateException`; outer field name and original outer code through `Field`/`FieldCode`; nested type and name when available in the message; original part URI and determinable paragraph/row context in `Location`/message; unsupported cached-result nesting explanation; concrete advice to move the nested field outside or replace the outer result with plain cached text. An unavailable nested name must not invent one. Never use raw runtime exceptions or stack traces as the primary message.
6. F2-S1 rejection safety: no `MergeResult` is returned; caller stream remains open/readable and its bytes unchanged, without requiring its original position to remain unchanged because `Merge` consumes input. Use a fresh valid merge on the same injected engine after rejection to prove metadata/options/context do not leak.

## 6. F3 — reject independent region footprint conflicts

1. Correction: retain every matched region interval and logical parent in `RegionParser` validation. At each parent compare independent sibling footprints derived from inclusive `GetBlocks` sibling ranges. Shared blocks or ancestor/descendant containment between their affected blocks is unsupported. Check same-name sequential regions as well as different names. Preserve genuine logical parent/child nesting; physical intersection alone must not reject it.
2. F3-R1 Red reproducer: one paragraph holds sequential A and B regions with item Name fields and populated arrays. Expect contextual `TemplateException`; current code throws `NullReferenceException` after deleting their shared paragraph. Validate fixture structure and assert both collection names plus paragraph location and separate-block correction advice.
3. F3-R2 footprint matrix: sequential regions sharing a table row with markers in different cells; multi-block regions sharing a boundary paragraph/row; same-name independent regions; a region using a containing row and an independent region inside its nested table/paragraph; disjoint logical intervals with ancestor physical footprint intersections. Assert contextual rejection instead of detached-node/runtime exceptions for each case.
4. F3-R3 nested conflicts: independent sibling conflicts inside a genuine parent region, at more than one nesting depth. Exercise populated, empty, missing, and null parent collections; invalid original templates must reject even when zero clones would render. Existing malformed marker order/name mismatch must retain structural rejection and useful context.
5. F3-P1 controls: ordinary scalar fields within paragraphs; a single inline-marker region; separate disjoint paragraph/row ranges; multiple independent regions including same-name regions on separate supported blocks; valid nested paragraph/table collections, including same-name parent/child nesting; zero/one/many items; inline markers within one supported row; headers outside repeated regions; parent/root context restoration. Assert values/counts, field codes, complete selected formatting, technical marker removal, and Open XML validity. Do not require repeat generation of collections from output after marker removal.
6. F3-D1 assertions: `TemplateException` with both collection names, original contextual code, unsupported shared/overlapping-block explanation, part URI plus determinable paragraph/table-row location, and advice to use separate supported block ranges without a shared boundary. For same-name regions identify two conflicting occurrences through their locations. Apply section 5.6 rejection safety and reusable-engine checks here too.

## 7. Package-wide timing and diagnostic integration

1. MergeEngine must finish original-tree F2/F3 preflight for main document, headers, footers, footnotes, and endnotes before the first replacement, marker removal, cloning/removal, or part write. Keep XML trees in a local per-operation list with their part URIs; then use the existing render/save sequence. Renderer preflight invokes field validation and complete-depth region validation without data-dependent traversal. Defensive clone validation is permitted but cannot replace original preflight.
2. T1 test matrix places each invalid F2/F3 fixture in each rendered story kind, with ordinary valid fields/regions in earlier parts. Include later-part defects after a main field whose configured test formatter records invocation or throws a distinct sentinel if called. Assert structural `TemplateException` wins and formatter invocation count is zero; this demonstrates preflight precedes rendering rather than merely proving that caller bytes are copied. Add a valid earlier empty region to demonstrate preflight is independent of cloning.
3. T2 directly exercise nonmutating renderer/parser preflight with saved original XML snapshots containing invalid later fields/regions and compare whole trees after rejection. Inspect MergeEngine integration in independent review to verify all-tree validation precedes every story write; exception/no-result alone cannot prove internal ordering. Avoid a new production mocking architecture solely to observe writes.
4. T3 positive multi-story fixture includes a successful scalar merge in every existing story kind, retained sibling Word fields, and a supported region where valid. Validate package relationships, footnote/endnote definitions, complete output schema, exact story values and codes, and reuse the engine across separate operations. Extend existing header/footer fixture patterns with valid footnote/endnote packages rather than constructing schema-invalid negative fixtures.
5. Locations are derived on original XML before mutation: part URI plus stable one-based document-order paragraph indices or an unambiguous structural path; include table/row indices where determinable. Test distinct repeated collection occurrences and fields in different cells. Never promise a Word page number. Use existing `TemplateException` properties and CLI message-only handling.
