24. Blocking finding 1, specification conformance and correctness: `MonoReport/Services/TemplateStructureValidator.cs`, lines 13–20, remains fail-fast for an entire readable story. It catches at most one field-stage exception and only runs the region stage when no field error exists. `OoxmlFieldParser.Validate` and `RegionParser.Validate` also throw on the first issue. This does not implement approved Feature Spec items 38, 64–66 or Implementation Plan items 9 and 31, which require collecting independently detectable structural failures within trustworthy same-story stages, including multiple safe nested-field, boundary, and overlap defects. Requested fix: implement deterministic per-rule/per-anchor diagnostic collection for safe stages, preserve fail-fast only after corrupt parser state, deduplicate diagnostics, route generation to the first deterministic shared diagnostic, and add focused Core and adapter tests proving the approved aggregation boundary.
25. Blocking finding 2, required actual-process coverage: `MonoReport.Tests/Services/CliProcessTests.cs` contains ten cases, but all ten exercise existing generation/help/error behavior; none invokes `--validate`. The Developer statement in item 9 describes the class count as CLI validation coverage even though the new mode is covered only by in-process tests and the separate parity-process test. This omits Feature Spec item 87 and Implementation Plan item 62: actual CLI entry-point cases for valid, structurally invalid, corrupt and empty templates, every forbidden/duplicate/missing argument category, nonexistent files, help, and a validation process that exits while redirected stdin remains open. Requested fix: add the approved actual-process matrix, including bounded waits and clean stdout/stderr assertions, and correct the verification record to distinguish generation and validation process cases.
26. Blocking finding 3, Core acceptance coverage: `MonoReport.Tests/Services/TemplateValidatorTests.cs` has only four cases. It does not directly cover every supported story and structural category, current-position and non-seekable streams, content preservation, null/unreadable arguments, deterministic same-story diagnostic ordering and deduplication, unsafe-stage stopping, concurrent validation, independently unreadable parts, or operational I/O propagation. Some categories appear in HTTP or legacy generation tests, but the approved Feature Spec items 64–66 and Implementation Plan items 30–31 explicitly require Core validator and shared-rule verification. Requested fix: add focused Core tests for these public API and aggregation guarantees, including evidence that standalone validation never evaluates data or formatters.
27. Blocking finding 4, documentation accuracy: README.md states that `TemplateValidator` leaves the caller-owned input “open and unchanged.” The implementation copies from the stream's current position and advances that position, as allowed by Feature Spec item 31. The current wording can reasonably promise unchanged position. Requested fix: state explicitly that the caller retains ownership, content is not modified, the stream remains open, and its position may advance.
28. Independent outcome: CHANGES REQUESTED. The build and current 296-test suite pass, the separate API boundary, generated OpenAPI, HTTP contracts, request-limit behavior, Swagger fallback implementation, retained Swagger UI workflows, CLI output separation, and broad regression suite are promising, but findings 24–27 block Reviewer PASS. The feature remains in review and must return to the Developer for correction followed by independent re-review.
